# Architecture Documentation: Remote VS Code Controller

## 1. High-Level System Architecture

Remote VS Code Controller provides dedicated, isolated application-level remote access to Visual Studio Code on a Windows host (Provider) from another machine (Controller).

Unlike traditional remote desktop tools (RDP, VNC, AnyDesk), the Controller **never captures the Provider's active desktop** and **never injects global keyboard or mouse events** into the Provider's session.

```
+-----------------------------------------------------------------------------------+
|                           CONTROLLER DESKTOP APP                                  |
|   (Electron + React 18 + Vite + Tailwind CSS + xterm.js + WebRTC Data Channels)   |
+----------------------------------------+------------------------------------------+
                                         |
                                         | WSS / TLS 1.3
                                         v
+-----------------------------------------------------------------------------------+
|                        CONNECTION SIGNALING SERVER                                |
|   (Fastify + WebSockets + JWT Authentication + SDP/ICE Broker + Audit Logging)    |
+----------------------------------------+------------------------------------------+
                                         |
                                         | WSS / TLS 1.3
                                         v
+-----------------------------------------------------------------------------------+
|                             PROVIDER AGENT                                        |
|   (Node.js Daemon / Background Agent + Windows Process Isolation Manager)         |
+-------------------+--------------------+-------------------+----------------------+
                    |                    |                   |
                    v                    v                   v
        +-----------------------+ +-------------+ +--------------------+
        | Dedicated VS Code     | | Isolated    | | Sandboxed          |
        | Server (Headless)     | | PTY Shells  | | File System Proxy  |
        | `code serve-web`      | | (node-pty)  | | (Path Guarded)     |
        +-----------------------+ +-------------+ +--------------------+
```

## 2. Component Breakdown

### 2.1 Controller Desktop Application (`apps/controller-desktop`)
- **Technology Stack**: Electron 30, React 18, TypeScript, Vite, Tailwind CSS.
- **Main Process**: Manages application lifecycle, window management, context isolation, and IPC bridges.
- **Preload Bridge**: Exposes safe, typed methods via Electron `contextBridge`. Direct `nodeIntegration` is strictly disabled.
- **Renderer Process**:
  - `Dashboard`: Device registry, discovery, pairing PIN dialog, session launcher.
  - `RemoteWorkspace`: Embedded VS Code session canvas, integrated collapsible side panels.
  - `TerminalView`: Multi-tab xterm.js remote terminal.
  - `FileManager`: Tree explorer, directory navigation, file uploads/downloads, inline text preview.

### 2.2 Provider Agent (`apps/provider-agent`)
- **Technology Stack**: Node.js, TypeScript, Express, WebSocket (`ws`), `node-pty`.
- **VSCodeProcessManager**: Dynamically finds free TCP ports and spawns `code serve-web --host 127.0.0.1 --port <dyn> --server-data-dir <isolated_dir> --connection-token <token>` in hidden mode (`windowsHide: true`).
- **IsolationManager**: Creates ephemeral `user-data` and `extensions` directories under `~/.remote-vscode/sessions/{sessionId}`. Guarantees that settings, caches, and plugins never pollute the Provider's local VS Code.
- **TerminalManager**: Spawns independent pseudo-terminals (PowerShell 7/5, CMD, Git Bash) rooted strictly within the authorized workspace.
- **FileSystemManager**: Secure file operations preventing directory traversal via canonical `fs.realpathSync` validation.
- **PermissionManager**: Manages session-level approval, granular permissions (read, write, terminal, debug), and audit logs.

### 2.3 Connection Signaling Server (`apps/signaling-server`)
- **Technology Stack**: Node.js, Fastify, WebSocket (`ws`), JWT (`jsonwebtoken`).
- **Device Registry**: Tracks connected Provider agents and Controller clients, heartbeat health, and pairing states.
- **Pairing Broker**: Validates 6-digit cryptographic pairing PINs generated by Providers.
- **Signaling Handler**: Mediates WebRTC SDP offer/answer exchanges and ICE candidates for peer-to-peer tunnels.
- **Session Manager**: Manages end-to-end active session lifecycles, timeouts, and revocation notifications.

### 2.4 Shared Protocol & Utilities (`packages/shared`)
- **Message Contracts**: Typed envelopes (`createEnvelope`, `isEnvelope`), session approval payloads, terminal RPCs, filesystem commands.
- **Security Validators**: Workspace path validation, filename sanitization, permission guards.
- **Constants**: Default ports, heartbeat intervals, error codes.

## 3. Dedicated Session Isolation Strategy

To satisfy the non-interference requirement on Windows:

1. **Headless Execution**: `code serve-web` executes with `windowsHide: true` and `stdio: ['ignore', 'pipe', 'pipe']`. No Win32 window is registered on the active desktop.
2. **Dedicated User Profile**: An isolated directory tree is created for every session:
   ```
   %USERPROFILE%\.remote-vscode\sessions\<sessionId>\
   ├── user-data\
   │   └── User\settings.json
   └── extensions\
   ```
3. **No Win32 Global Input Hooks**: Injected keystrokes and clicks never invoke Win32 `SendInput` or `mouse_event`. All Controller input flows exclusively over the secure tunnel into the isolated web editor instance.
4. **Session Teardown**: When the session disconnects, the Provider Agent terminates the child process tree (`taskkill /F /T /PID <pid>`) and purges ephemeral cache files.
